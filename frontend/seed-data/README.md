# Bucket Jeju M3 15일 Join 시드 데이터

> **임시 테스트 데이터:** 테스트 종료 후 `bucket-jeju-m3-seed.synthetic.json`과 웹 연결 코드를 함께 삭제할 수 있습니다.

> **합성 데이터 안내:** 이 폴더의 모든 투숙객·닉네임·객실·침대·숙박기간·조인 요청 및 참여 관계는 M3 개발·디자인·테스트를 위해 임의 생성한 가상 데이터입니다. 실제 인물, 숙박 기록, 예약 또는 모임을 나타내지 않습니다.

## 데이터 구성

- 가상 투숙객 30명
- 조인 요청 60건(15일 동안 날짜별 1~7건 무작위 배정)
- 2026-08-01부터 2026-08-15까지 15일
- 날짜마다 1~7건으로 불균등하게 랜덤 배치
- 숙소 구분 없음
- 객실·침대는 실제 객실 정원 범위에서 중복 없이 임의 배정
- 닉네임만 사용하며 이름·이메일·전화번호는 포함하지 않음
- 고정 난수 seed `20260731`을 사용하여 언제나 같은 결과 재생성

## 투숙객 필드

- `id`, `nickname`
- `checkInDate`, `checkOutDate`
- `roomNumber`, `bedNumber`, `bedKey`
- `interests`, `profileKeywords`
- `stayVerificationStatus`
- `isSynthetic`

## Join 필드

- `id`, `title`, `description`
- `category`, `keywords`
- `scheduledDate`, `scheduledTime`, `location`
- `hostGuestId`, `hostNickname`
- `maxParticipants`, `currentParticipants`
- `status`, `participantGuestIds`
- `isSynthetic`

## 키워드 범위

운동·러닝·산책·트레킹·요가·자전거·플로깅·식사·혼밥탈출·고기국수·흑돼지·카페·디저트·사진·필름사진·일출·노을·별보기·독서·오름·해변·숲·시장·섬여행·로컬문화·친목·대화·드라이브 등을 사용합니다.

## 재생성

```bash
node frontend/seed-data/generate-seed.mjs
```

## 검수 기준

- `guests.length === 30`
- `joinRequests.length === 60`
- 조인 일정이 정확히 15일 안에 존재
- 15일 모두 최소 1건 이상의 조인이 존재
- 날짜별 조인 수에 차이가 있으며 최소 1건, 최대 7건
- 작성자와 참여자가 해당 일정에 투숙 중
- 닉네임과 배정 침대가 중복되지 않음
- 모든 레코드의 `isSynthetic === true`
- `currentParticipants <= maxParticipants`

## 버전 및 디버깅 기록

기존 데이터 명세와 생성 방법은 위 내용을 유지하며, 배포·수정 이력은 아래에 계속 누적합니다.

### v1 — 기초 배포용

- 제주 감성의 반응형 기본 UI 구성
- 홈, 근처 발견, Join, 프로필 화면 구성
- 버킷제주 위치 중심의 지도 화면 구성
- Join 카드 및 참여 버튼 기본 동작 구현
- 초기 데모용 소수의 임시 Join 데이터 사용

### v2 — 투숙객 30명·Join 60건 적용

#### 수정 및 변경 사항

- 가상 투숙객을 30명으로 생성
- 2026-08-01부터 2026-08-15까지 최대 15일 일정 구성
- Join 요청을 60건으로 확대하고 날짜별 1~7건으로 불균등 배치
- 산책, 식사, 운동, 사진, 카페, 자전거, 친목, 여행, 요가 등 다양한 키워드 분배
- 각 투숙객에 닉네임, 입실일, 퇴실일, 객실 번호 및 침대 번호를 부여
- Join 작성자와 참여자는 해당 일정에 실제 투숙 중인 합성 사용자만 연결
- 모든 데이터에 `isSynthetic: true`를 기록하고 합성 데이터임을 문서와 파일 헤더에 명시
- Join 화면에 키워드 필터와 참여·취소 동작 연결
- 지도 화면에 버킷제주 고정 위치 기준 반경 2km 안내 추가
- 프로필 테스트 화면은 활동 키워드 중 최대 5개만 표시

#### 디버깅 및 검증 결과

- [완료] `guests.length === 30`
- [완료] `joinRequests.length === 60`
- [완료] 일정 시작일 `2026-08-01`
- [완료] 일정 종료일 `2026-08-15`
- [완료] 전체 일정 기간 15일
- [완료] 날짜별 Join이 1~7건으로 다르게 배정됨
- [완료] 투숙객 30명의 객실·침대 배정 중복 없음
- [완료] 작성자와 참여자의 일정별 투숙 자격 검증
- [완료] 모든 레코드의 합성 데이터 표시 확인
- [완료] 웹 앱 배포용 빌드 성공
- [완료] 서버 렌더링 테스트 통과
- [수정] 최초 생성 시 종료일이 `2026-08-14`로 계산되던 시간대 오류를 UTC 날짜 계산 방식으로 수정
- [수정] 웹 소스의 깨진 한글 문자열과 손상된 화면 코드를 정상화
- [대기] Sites 배포 저장소 연결 제한으로 현재 운영 URL의 v2 재배포는 아직 완료되지 않음

### v3 — 날짜별 Join 불균등 랜덤 배정

#### 수정 및 변경 사항

- 총 Join 60건과 전체 15일 조건은 그대로 유지
- 매일 4건이던 균등 배정을 날짜별 1~7건의 불균등 배정으로 변경
- 조인이 많은 날과 적은 날이 함께 나타나도록 일별 건수 구성
- 고정 난수 seed `20260731`로 날짜 배치를 섞어 재생성 결과를 동일하게 유지
- JSON 메타데이터에 `joinDistribution`, `minimumJoinsPerDay`, `maximumJoinsPerDay` 추가

#### 디버깅 및 검증 결과

- [완료] 전체 Join 합계 60건
- [완료] 일정 범위 `2026-08-01`~`2026-08-15`
- [완료] 15일 모두 최소 1건 이상의 Join 존재
- [완료] 일별 최소 1건, 최대 7건
- [완료] 같은 seed로 실행할 때 동일한 날짜별 분포 재생성

#### 관련 파일

- `bucket-jeju-m3-seed.synthetic.json`: 합성 투숙객 30명과 Join 60건
- `generate-seed.mjs`: 동일한 데이터를 다시 생성하는 고정 시드 스크립트
- `README.md`: 데이터 명세, 버전 기록 및 디버깅 결과

### v4 — FastAPI 연결 및 충돌 점검

#### 수정 및 변경 사항

- 빈 백엔드 파일에 `/health`, `/api/v1/joins`, `/api/v1/joins/{id}`, `/api/v1/guests` 구현
- 프런트에 `API_BASE_URL` 기반 Join API 클라이언트 추가
- API가 실행되지 않을 때 동일한 합성 JSON을 읽는 자동 폴백 추가
- 기존 카카오 지도 코드는 유지하고 Streamlit 사이드바에 Join 화면을 독립적으로 추가
- 닉네임 외 이름·이메일·전화번호는 API 응답에 포함하지 않음
- API 목록에 날짜·상태·키워드 필터와 페이지 크기 적용

#### 충돌 및 검증 결과

- [완료] `m3`와 `main` 비교: `m3`는 6커밋 앞, 1커밋 뒤의 diverged 상태
- [완료] 백엔드 공용 파일은 `main`, `m3` 모두 빈 파일임을 확인하여 구현 충돌 없음
- [완료] 기존 `frontend/app.py`의 카카오 지도 코드를 유지
- [완료] 시드 데이터 경로와 API 응답 필드 일치 확인
- [완료] API 미연결 환경에서도 Join 60건 표시 가능
- [주의] `m3`를 `main`에 병합하기 전 뒤처진 1개 커밋을 먼저 반영하고 최종 충돌 확인 필요
