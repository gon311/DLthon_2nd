# RAG 평가서 — 「버킷 제주」 근거리 정보 검색 품질

- **팀:** DLthon TEAM 3 (PL · M1 · M2 · M3)
- **작성일:** 2026-08-10 · **발표:** 2026-08-11
- **대상:** 숙소 반경 2km 근거리 정보 RAG + 게스트하우스 FAQ

---

## 1. 목적

"우리 RAG가 얼마나 잘 찾고, 얼마나 안 지어내는가"를 **수치로 증명**하기 위한 평가. 발표에서 정확도(Recall@3)·재랭킹 품질(Top-1)·환각 방지(함정 질문)를 숫자로 제시하는 것을 목표로 한다.

## 2. RAG 파이프라인 (평가 대상)

```
질문 → 임베딩(text-embedding-3-small) → ChromaDB 검색(상위 10)
     → 혼밥 친화도(solo_friendly) 재랭킹 → 숙소 기준 거리(haversine) 재랭킹
     → 상위 3개 → LLM 자연어 답변(장소 설명·출처 포함)
```

핵심은 단순 벡터검색이 아니라 **의미 유사도 + 혼밥 친화도 + 거리** 3개 신호로 재정렬하는 **위치인지(geo-aware) RAG**라는 점. 거리 계산은 `backend/utils/geo.py` 한 곳에서만 정의해 값 불일치를 원천 차단(PL·M1·M2·M3 동일 함수 사용).

## 3. 평가 데이터

| 평가셋 | 규모 | 담당 | 용도 |
|--------|------|------|------|
| gold_qa.json | 20 (poi_search) | PL | 근거리 정보 정답/골드 컨텍스트 |
| gold_matching.json | 15 | PL | 매칭 골드셋 |
| trap_questions.json | 8 (함정) | PL | 과장·환각 방지 검증 |
| **구어체 평가셋** | **29 (POI 14·FAQ 12·범위밖 3)** | **M3** | 실제 투숙객 말투 질의 + FAQ + 폴백 |

> 예) PL 골드셋 `QA-01`: "게스트하우스와 가장 가까운 편의점은?" → CU 서귀최남단해안로점.
> 예) M3 구어체셋 `q01`: "야 나 혼자 왔는데 걸어서 갈만한 밥집 어디 있어?" → 대정쌍둥이식당(102m).
> 예) trap `TRAP-01`: "모든 메뉴가 무한리필?" → "아니다, 일부 반찬만" (과장 금지).

## 4. 지표

- **Recall@3:** 정답 출처가 상위 3개 검색결과에 포함되면 hit.
- **Top-1 재랭킹 정확도:** 거리·혼밥 재랭킹이 맞으면 1위가 기대값과 일치.
- **환각/폴백 정확도:** 데이터에 없는 질문(2km 밖·미보유 팩트)에 "정보 없음/직원 문의"로 답하면 정답, 지어내면 오답.

## 5. 결과 (구어체 29문항 채점)

임베딩 없이 **키워드 매칭 + 거리·재랭킹만으로** 낸 하한선(오프라인 베이스라인)과, 순수 어휘 랭킹(BM25)을 비교했다.

| 지표 | 키워드 베이스라인 | BM25(순수 어휘) |
|------|------------------|-----------------|
| 근처 장소(POI) Recall@3 | **100.0%** (14/14) | 78.6% (11/14) |
| 게스트하우스 FAQ Recall@3 | **91.7%** (11/12) | 83.3% (10/12) |
| 범위밖 폴백 정확도 | **100.0%** (3/3) | 33.3% (1/3) |
| POI Top-1 재랭킹 | **88.9%** (8/9) | 66.7% (6/9) |
| **전체 평균** | **96.6%** (28/29) | 75.9% (22/29) |

임베딩 부분은 `OPENAI_API_KEY` + ChromaDB 인덱스가 있으면 동일 채점기(`rag_eval_runner.py --mode rag`)로 실제 점수를 산출할 수 있다.

## 6. 핵심 인사이트 (발표 어필 포인트)

- 키워드/BM25 같은 **순수 어휘 검색**은 단어가 글자 그대로 겹쳐야 맞는다. 그래서 "밥집↔한식", "**담배↔흡연**", "역사↔전시관", "상비약↔응급약품" 같은 **동의어·의미 간극을 놓친다.** (BM25 단독이 76%로 떨어진 이유)
- 유일한 베이스라인 오답도 **"담배는 어디서 피워?"** — FAQ엔 "흡연 장소"로 적혀 있어 단어가 안 맞은 케이스. **임베딩 RAG는 의미로 매칭하므로 바로 이 간극을 해결**한다.
- 반대로 BM25는 "25시해장국", "CU" 같은 **고유명사·숫자**에 강하다.
- **결론:** BM25(어휘) + 임베딩(의미)을 **RRF(Reciprocal Rank Fusion)** 로 합친 **하이브리드**가 양쪽 약점을 서로 메운다. 발표 스토리: "BM25 76% → 임베딩으로 동의어 보완 → 하이브리드로 최고".

## 7. 환각 방지

범위밖 3문항("성산일출봉 버스 시간", "체크인 시간", "반려동물 정책")은 **데이터에 없는 질문**으로, 지어내지 않고 폴백해야 정답. 키워드 베이스라인은 폴백 3/3(100%)이었으나 BM25는 점수 하한(gate) 없이 조금이라도 겹치면 결과를 내 1/3로 하락 → **"융합 점수가 임계값 미만이면 정보 없음/직원 문의" 게이트**를 두면 복구된다. PL의 trap_questions(8개)와 함께 과장·환각을 이중으로 검증.

## 8. 역할별 기여 (평가 관점)

- **PL:** 골드셋(gold_qa 20·gold_matching 15·trap 8) 설계·라벨링, 신뢰도 점수·할루시네이션율 정의, 인덱싱.
- **M1:** 평가의 근거가 되는 실데이터(POI 21곳) 수집·정제 — 좌표·거리·`solo_friendly`의 정확도 토대.
- **M2:** 채점 대상 검색·재랭킹 로직(`/nearby-search`, 하버사인, 2km 반경) 구현.
- **M3:** 실제 투숙객 말투 구어체 평가셋(29문항)·오프라인 채점기 작성, 베이스라인/BM25 비교·하이브리드 제안.

## 9. 한계 & 다음 단계

- 현재 수치는 **임베딩 없는 하한선**이다. 실제 임베딩 RAG 점수는 동의어 처리로 더 높을 것으로 기대 → 키 연결 후 재측정.
- 하이브리드(BM25+임베딩+RRF) + 폴백 게이트 적용 후 재평가.
- 골드셋을 gold_qa 20 + 구어체 29로 통합해 카테고리별 Recall@3·환각율 표를 발표 슬라이드에 수록.
- POI 하드코딩(21곳) → 데이터 파이프라인/DB 기반 자동 갱신 시 평가셋도 주기적 갱신.
