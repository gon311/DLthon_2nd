## 슬라이드별 상세 계획

### S1. 표지
- **목적:** 서비스 한 줄 각인
- **메시지:** "혼자 온 게스트하우스 투숙객을 위한 근처 발견 + 순간 동행(Join) 서비스"
- **담을 내용:** 서비스명(버킷 제주), 팀명·팀원(PL/M1/M2/M3), 발표일, 운영 웹 QR
- **시각:** 지도+마커 히어로 이미지 / 라이브 URL QR
- **발표자:** PL

### S2. 문제 정의
- **목적:** 왜 이 서비스인가
- **메시지:** 혼자 여행자는 ①숙소 주변 정보가 흩어져 있고 ②혼밥·동행이 어렵다
- **담을 내용:** 게스트하우스 특별서비스 니즈(관광안내 26.1%, 공동투어 필요성 등 레퍼런스), 페인포인트 3가지
- **시각:** 페인포인트 아이콘 3개, 근거 수치 1~2개
- **발표자:** PL

### S3. 솔루션 개요
- **목적:** 해결 방식 한눈에
- **메시지:** 숙소 반경 2km 안에서 "물어보면 답해주는" 근거리 정보 + Join 커뮤니티
- **담을 내용:** 3대 축 — 근처 발견(2km RAG 검색) · Join(순간 동행) · AI 안내(게스트하우스 FAQ)
- **시각:** 3-축 다이어그램
- **발표자:** PL

### S4. 라이브 데모
- **목적:** 실제 동작 증명(가장 강한 설득)
- **메시지:** "지금 켜져 있습니다"
- **담을 내용:** 근처 발견 지도(2km 원형 가이드+카테고리 필터) → 장소 상세 → Join 작성/3상태 → AI 질문 탭
- **시각:** 라이브 화면 or 30초 녹화 GIF, 실패 대비 스크린샷 백업
- **발표자:** M3

### S5. 팀 구성 & 역할 (순차 흐름)
- **목적:** 누가 무엇을, 어떻게 이어졌는지
- **메시지:** 데이터→지식베이스/RAG→백엔드→프론트로 이어지는 파이프라인 분업
- **담을 내용(표):**
  | 역할 | 담당 | 핵심 산출물 |
  |------|------|-------------|
  | **PL** | 프로젝트 리드 | API 계약 설계·동결, KB 스키마, RAG 파이프라인·인덱싱, 평가 골드셋, 통합/PR 병합 |
  | **M1** | 데이터 | POI 수집·정제(카카오 21곳), EDA, `solo_friendly`·설명 생성 |
  | **M2** | 백엔드 | `/nearby-search` RAG API, 하버사인 거리, 2km 고정 반경, 재순위화 |
  | **M3** | 프론트엔드 | 웹데모, 2km 근처 발견 지도, 카테고리 필터, Join 3상태, D1·Drizzle |
- **시각:** 파이프라인 화살표(M1→PL→M2→M3) + PL 오케스트레이션
- **발표자:** PL

### S6. [M1] 데이터 — 수집·정제
- **목적:** 신뢰할 수 있는 실데이터임을 어필
- **메시지:** 카카오 실좌표 기반 21개 POI를 3단 파이프라인으로 정제
- **담을 내용:** `collect_pois.py`(카카오 수집+정류장 매핑) → `json_to_csv.py`(필드·category_norm) → `generate_description.py`(설명+solo_friendly). 재실행 순서 고정 규칙
- **시각:** 파이프라인 3단계 + POI 표본 몇 개
- **발표자:** M1

### S7. [PL] 지식베이스 · RAG 파이프라인
- **목적:** 기술 코어 어필
- **메시지:** POI를 자연어 문서화→임베딩→ChromaDB 인덱싱, 재랭킹까지 설계
- **담을 내용:** KB 스키마(문서화 규칙), `build_index.py`(거리 계산+임베딩+인덱싱), 숙소 좌표 단일 정의(`geo.py`), 평가 골드셋(gold_qa 20·gold_matching 15·trap 8)
- **시각:** RAG 파이프라인 다이어그램
- **발표자:** PL

### S8. [M2] 백엔드 — 근거리 검색 API
- **목적:** 서비스 엔진 설명
- **메시지:** 질의→검색→재랭킹→답변을 API로 제공
- **담을 내용:** `POST /nearby-search`, 하버사인 거리·**2km 고정 반경**, 카테고리 매핑, 빈 결과 200 처리, 신뢰도 점수
- **시각:** 요청/응답 예시 JSON 1개
- **발표자:** M2

### S9. [M3] 프론트엔드 — 지도·Join (공주님)
- **목적:** 사용자 경험 어필
- **메시지:** 2km 지도 위에서 바로 발견하고, 순간 동행을 만든다
- **담을 내용:** 반경 2km 원형 가이드, 카카오 실좌표 검수 마커(바다 오표기 제거), 카테고리 필터(식당·편의점·해변·관광·주차장), 장소 상세 패널, Join 모집중/모집완료/일정완료 3상태, 닉네임·D1·Drizzle
- **시각:** 지도 스크린샷 before/after(가짜좌표→실좌표)
- **발표자:** M3

### S10. RAG 품질 평가 (수치 어필)
- **목적:** "정확도"를 숫자로 증명
- **메시지:** 골드셋+구어체 평가로 정확도·환각 방지를 정량화
- **담을 내용:** 평가셋(gold_qa 20 + trap 8 + 구어체 29문항), 지표(Recall@3·Top-1·환각율), 결과(오프라인 베이스라인 96.6%, BM25 단독 76%) → **하이브리드(BM25+임베딩+RRF)** 권장
- **시각:** 정확도 막대그래프, 담배↔흡연 동의어 사례
- **발표자:** PL(평가 총괄) 또는 M3

### S11. 협업 & 통합 (PR 흐름)
- **목적:** 팀 협업 성숙도 어필
- **메시지:** 3단 저장소 + PR 기반으로 충돌 없이 통합
- **담을 내용:** 1차 개인 → 2차 포크(m3) → 3차 팀(M3) 구조. PR 흐름 — PL RAG 파이프라인(#1·#5·#6·#8·#9), M3 웹데모(#7 병합→#10 main), 최신 2km 지도(#11 병합 대기)
- **시각:** 저장소 3단 + PR 타임라인
- **발표자:** PL

### S12. 상용화 & 수익 모델
- **목적:** 확장 가능성
- **메시지:** 초지역 타깃 광고가 가장 적합
- **담을 내용:** 상용화 관문(데이터 파이프라인·독립 인증·정식 인프라·안전장치), 수익(지역 스폰서 플레이스★·예약 어필리에이트·제휴 쿠폰)
- **시각:** 우선순위 체크리스트(🔴🟡🟢)
- **발표자:** PL
