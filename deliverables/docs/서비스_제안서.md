## 1. 배경 & 문제

혼자 여행하는 게스트하우스 투숙객은 두 가지 어려움을 겪는다. 첫째, 숙소 주변 정보(맛집·편의점·해변·주차 등)가 여러 앱에 흩어져 있어 "지금 여기서 걸어갈 만한 곳"을 빠르게 찾기 어렵다. 둘째, 혼밥·투어 등에서 잠깐 함께할 동행을 구하기 어렵다. 게스트하우스 운영 현장 조사에서도 관광안내(26.1%) 등 정보 제공 니즈와 공동투어 프로그램의 필요성이 확인된다.

## 2. 타깃 사용자

제주 대정읍 모슬포 지역 게스트하우스(버킷 제주) 투숙객, 특히 **혼자 여행하는 20~30대**. 짧은 체류 동안 근처 정보를 즉시 얻고, 부담 없이 순간 동행을 만들고 싶어 하는 사용자.

## 3. 솔루션 개요

숙소를 중심으로 한 **반경 2km "정보 제공 경계"** 안에서 동작하는 3-축 서비스.

1. **근처 발견 (RAG 검색)** — "혼자 갈 만한 밥집?"처럼 자연어로 물으면, 의미 유사도 + 혼밥 친화도 + 거리 3개 신호로 재랭킹해 가까운 순으로 추천.
2. **Join (순간 동행)** — 투숙객이 밥·투어 등 짧은 동행 모집글을 올리고, 모집중/모집완료/일정완료 상태로 관리.
3. **AI 안내 (게스트하우스 FAQ)** — 와이파이·이용시간·규칙 등 숙소 이용 문의를 즉시 응답(RAG 연결 준비).

## 4. 핵심 기능

- 근처 발견 지도: 반경 2km 원형 가이드 + 카카오 실좌표 검수 마커(21곳), 바다 위 오표기 제거
- 카테고리 필터: 식당🍽️ · 편의점🏪 · 해변🏖️ · 관광📷 · 주차장🅿️ (지도·목록 동시)
- 장소 상세 패널, 거리순 표시
- Join 작성·조회, 3상태 분리, 예정/지난 일정 구분, 메인 최신 노출
- 닉네임 변경(2~20자, 영구 저장), ChatGPT 로그인 기반 사용자 식별

## 5. 차별점

- **초지역·위치인지(geo-aware) RAG:** 단순 검색이 아니라 숙소 기준 거리와 "혼자 여행" 프로필을 반영해 재랭킹.
- **실데이터 기반:** 카카오 실좌표로 검수한 실제 POI(21곳) — 지어낸 좌표·바다 마커 제거.
- **환각 방지 설계:** 확인 안 된 정보는 단정하지 않고, 함정 질문(trap) 평가로 검증.

## 6. 기술 스택 & 아키텍처

- **프론트엔드:** React 19 + TypeScript + Vinext, Leaflet 지도, Cloudflare D1 + Drizzle ORM
- **백엔드/RAG:** FastAPI, OpenAI Embeddings(text-embedding-3-small), ChromaDB, 하버사인 거리(`geo.py` 단일 정의)
- **데이터:** 카카오 로컬 수집 → CSV 정제 → 설명·`solo_friendly` 생성 → 인덱싱
- **배포:** OpenAI Sites(웹데모), 저장소 3단(개인 → 포크 → 팀) + PR 통합
